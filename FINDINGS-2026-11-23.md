# Orchestra findings, 2026-11-23

Scope: can fleet models run as Claude Code's local subagents, and what state is Orchestra in before it is upgraded? Companion plan: `UPGRADE-PLAN-v21.md`.

No Orchestra file was changed. Tests ran on a copy in a scratch folder.

## 1. Answer

Yes. Claude Code can run with a fleet model as its only model, through OpenRouter's Anthropic-compatible Messages endpoint. Claude Code supplies the tools and permissions; the fleet model does the reasoning.

This is shown for **one model, one small task, with Read and Edit only**. It is not yet shown for long runs, shell access or a swarm.

## 2. Proof of concept

**Direct API probe.** `POST https://openrouter.ai/api/v1/messages` with `meta/muse-spark-1.3` and a forced tool returned HTTP 200 and a valid `tool_use` block: `add(a=2, b=3)`.

**Worker run.** Claude Code 2.1.328, headless (`-p`), asked to fix a broken `median()`.

| Item | Result |
|---|---|
| Test before / after | fail / **pass** (run outside the worker) |
| Claude Code turns | 4 |
| OpenRouter requests | 3 |
| Time | 9.3 s |
| Tokens | 10,272 input including 3,539 cache read; 727 output |
| Real cost (OpenRouter log) | about $0.012 |
| Claude Code's cost estimate | $0.042, about 3.5x too high |
| Host | Meta |

Isolation used: throwaway folder, empty home directory, scrubbed environment, tools limited to `Read,Edit`, no MCP servers, no setting sources, 8-turn limit.

Worker configuration:

```text
ANTHROPIC_BASE_URL=https://openrouter.ai/api
ANTHROPIC_AUTH_TOKEN=<OpenRouter key>
ANTHROPIC_API_KEY=
ANTHROPIC_MODEL=meta/muse-spark-1.3
ANTHROPIC_SMALL_FAST_MODEL=meta/muse-spark-1.3
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1

claude -p "<task>" --model meta/muse-spark-1.3 --tools "Read,Edit" \
  --allowedTools "Read,Edit" --permission-mode acceptEdits --max-turns 8 \
  --strict-mcp-config --setting-sources "" --output-format json
```

### What the run taught

1. **OpenRouter is the billing record.** Claude Code's cost for unknown models is unreliable (`costBasis: unknown`), so `--max-budget-usd` cannot be trusted as the cap until tested.
2. **Hosts change between calls.** The same model went to Meta and to Google. Muse Spark has `pin=None` in the registry.
3. **Turns are not requests** (4 against 3).
4. **Claude Code logs `unrecognized_model`** for this id but runs. Features that depend on known model metadata may differ.

### Solar Decide diagnosis (D10)

Scripts: `docs/diagnostics/solar_wording_test.py`, `docs/diagnostics/solar_ratification_test.py`. Labels were fixed before the runs.

**Parity test, 8 numbers per wording (accuracy):**

| Wording | Solar | Jev |
|---|---|---|
| Terse, "Is `number` even?" | 6/8 | 8/8 |
| Same, with true/false criteria | 8/8 | 8/8 |
| Plain-string state | 8/8 | 8/8 |
| Explicit rule | 8/8 | 8/8 |
| Negated, terse | 8/8 | 8/8 |
| Negated, with criteria | **4/8** | 8/8 |
| "Is it odd?" | **5/8** | 8/8 |
| "Is this FALSE?" | **5/8** | 8/8 |
| Explicit negated rule | 6/8 | 8/8 |

**Ratification-style test, 16 source/summary pairs, each asked both ways:**

| Model | "All supported?" | "Contains an unsupported claim?" | False results at the 0.80 bar (inverted form) | Polarity gap |
|---|---|---|---|---|
| Solar | 14/16 | **11/16** | **5** | 0.299 |
| Jev | 16/16 | 16/16 | 0 | 0.017 |
| Decider v1.2 | 16/16 | 16/16 | 0 | 0.001 |

**Conclusion.** Solar is sensitive to wording, worst when "true" means something is absent, wrong or negative. This is not a transport or parsing fault: responses are well formed and the served build is correct. The internal cause cannot be seen from outside.

**Impact.** The standard ratification checklist uses the positive form, where Solar gave no false pass at 0.80, so past sign-offs were more likely over-blocked than wrongly passed. That is an inference from 16 items. Defect-style questions ("does it contain...") are the unsafe form. Router use is partly protected by the existing polarity check.

**Applied 2026-11-23.** The default panel is now Jev + Decider v1.2 (cross-class) in the server and packaged skill. Solar remains available for oversized states, with positive-form questions. Backup: `_backup_2026-11-23_pre-panel-change/`. A live panel call agreed across classes. Takes effect after the MCP server restarts and the skill is reinstalled.

**Still open.** Add a polarity canary to `fleet_check`. Solar is still third in the router chain, protected by the polarity check. Two of the three failing panel tests name the removed `inception/mercury-decide:free`, so they look stale; confirm the single-class guard when fixing them.

## 4. Limits of this evidence

- One model, one easy task, one run. It says nothing about reliability.
- `Bash`, subagents inside workers, long contexts, images and concurrency are untested.
- Other fleet models were not tried through this route.
- Read and Edit were restricted by tool list, not an OS sandbox. A worker with shell access needs real containment.
- Anything a worker reads is sent to its model provider.
